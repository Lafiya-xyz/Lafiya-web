## Overview

This document tracks the implementation of three enterprise-grade security transformations for the Lafiya healthcare platform:

1. **Issue #854:** DPoP proof-of-possession for partner API credentials (RFC 9449)
2. **Issue #855:** Centralized authorization with Cedar policy engine
3. **Issue #856:** Just-in-time privileged access with time-boxed elevation

These issues implement **Zero Trust security principles**: eliminate standing privileges, centralize policy decisions, and cryptographically bind credentials to clients. This represents a fundamental shift from traditional perimeter-based security to modern identity-centric security.

## Issue #854: DPoP Proof-of-Possession for Partner API Credentials

### Problem Statement

**Current State:**
- Partner API keys are **bearer tokens** (RFC 6750)
- Anyone with the token can use it from anywhere
- No binding between token and client identity
- Common leakage: mobile apps, integration servers, logs, monitoring

**Bearer Token Risk:**
```typescript
// Current: Pure bearer secret
Authorization: Bearer sk_partner_abc123xyz

// Problem: If leaked, attacker can use from anywhere:
curl -H "Authorization: Bearer sk_partner_abc123xyz" \
  https://api.lafiya.health/patients

// No way to detect misuse!
```

**Attack Scenarios:**
1. **Mobile App Decompilation:** Extract API key from APK/IPA
2. **Server Compromise:** Attacker steals key from integration server
3. **Log Leakage:** Key logged in monitoring/analytics systems
4. **Insider Threat:** Employee copies key from production config
5. **Supply Chain:** Third-party dependency exfiltrates key

**Impact:**
- Critical: Stolen token = unlimited API access
- Compliance: Violates least-privilege principle
- Detection: Cannot distinguish legitimate vs stolen token usage

### Technical Analysis

**DPoP (RFC 9449): Demonstrating Proof-of-Possession**

Instead of bearer tokens, bind tokens to client's private key:

```
Client generates key pair (public/private)
Client sends public key → Server
Server issues access token bound to public key
Client must prove possession of private key on EVERY request

Result: Stolen token is useless without private key
```

**DPoP Request Flow:**
```
1. Client generates ephemeral key pair (ES256)
2. Client registers public key with server
3. Server issues DPoP-bound access token
4. For each request:
   - Client creates DPoP proof (JWT signed with private key)
   - Client sends: DPoP proof + access token
   - Server validates: proof signature + token binding
   - Server processes request if valid

Stolen token without private key: REJECTED
```

**DPoP Proof JWT:**
```json
{
  "typ": "dpop+jwt",
  "alg": "ES256",
  "jwk": {
    "kty": "EC",
    "crv": "P-256",
    "x": "...",
    "y": "..."
  }
}
{
  "jti": "unique-request-id",
  "htm": "POST",
  "htu": "https://api.lafiya.health/patients",
  "iat": 1640995200,
  "ath": "hash-of-access-token"
}
```

### Implementation Plan

#### Phase 1: DPoP JWT Generation (Client-Side)

**File:** `lib/security/dpop.ts` (Client library for partners)
```typescript
import { SignJWT, generateKeyPair, exportJWK } from 'jose';
import { createHash } from 'crypto';

export interface DPoPKeyPair {
  publicKey: CryptoKey;
  privateKey: CryptoKey;
  jwk: any; // JSON Web Key
}

export interface DPoPProofOptions {
  method: string;      // HTTP method: GET, POST, etc.
  url: string;         // Full URL being accessed
  accessToken: string; // Access token being used
  nonce?: string;      // Server-provided nonce (optional)
}

/**
 * Generate DPoP key pair for partner client.
 * Partner should generate once and store securely.
 */
export async function generateDPoPKeyPair(): Promise<DPoPKeyPair> {
  // Generate ES256 (ECDSA P-256) key pair
  const { publicKey, privateKey } = await generateKeyPair('ES256');

  // Export public key as JWK for server registration
  const jwk = await exportJWK(publicKey);

  return { publicKey, privateKey, jwk };
}

/**
 * Create DPoP proof JWT for API request.
 * Must be called for EVERY request to prove possession of private key.
 */
export async function createDPoPProof(
  keyPair: DPoPKeyPair,
  options: DPoPProofOptions
): Promise<string> {
  const { method, url, accessToken, nonce } = options;

  // Hash access token (ath claim)
  const accessTokenHash = createHash('sha256')
    .update(accessToken)
    .digest('base64url');

  // Create DPoP proof JWT
  const proof = await new SignJWT({
    jti: generateJti(),       // Unique ID for replay protection
    htm: method,              // HTTP method
    htu: url,                 // HTTP URL
    iat: Math.floor(Date.now() / 1000),
    ath: accessTokenHash,     // Hash of access token
    ...(nonce && { nonce })   // Server nonce if provided
  })
    .setProtectedHeader({
      typ: 'dpop+jwt',
      alg: 'ES256',
      jwk: keyPair.jwk        // Public key in header
    })
    .sign(keyPair.privateKey);

  return proof;
}

/**
 * Generate unique JTI for replay protection.
 */
function generateJti(): string {
  return `${Date.now()}-${Math.random().toString(36).substring(2, 15)}`;
}

/**
 * Example usage for partner integration:
 * 
 * // One-time setup
 * const keyPair = await generateDPoPKeyPair();
 * // Store keyPair securely, send publicKey.jwk to Lafiya for registration
 * 
 * // For each API request
 * const dpopProof = await createDPoPProof(keyPair, {
 *   method: 'POST',
 *   url: 'https://api.lafiya.health/patients',
 *   accessToken: 'at_partner_xyz123'
 * });
 * 
 * // Send request with DPoP headers
 * fetch('https://api.lafiya.health/patients', {
 *   method: 'POST',
 *   headers: {
 *     'Authorization': `DPoP ${accessToken}`,
 *     'DPoP': dpopProof
 *   }
 * });
 */
```

#### Phase 2: DPoP Validation (Server-Side)

**File:** `lib/security/dpopValidator.ts`
```typescript
import { jwtVerify, importJWK } from 'jose';
import { createHash } from 'crypto';

export interface DPoPValidationResult {
  valid: boolean;
  reason?: string;
  claims?: any;
  publicKeyThumbprint?: string;
}

/**
 * Validate DPoP proof JWT from partner request.
 */
export async function validateDPoPProof(
  dpopProofJwt: string,
  request: {
    method: string;
    url: string;
    accessToken: string;
  },
  registeredPublicKeyJwk: any
): Promise<DPoPValidationResult> {
  try {
    // 1. Decode JWT header to extract public key
    const [headerB64] = dpopProofJwt.split('.');
    const header = JSON.parse(Buffer.from(headerB64, 'base64url').toString());

    // 2. Verify header
    if (header.typ !== 'dpop+jwt') {
      return { valid: false, reason: 'Invalid typ header (must be dpop+jwt)' };
    }

    if (header.alg !== 'ES256') {
      return { valid: false, reason: 'Invalid algorithm (must be ES256)' };
    }

    if (!header.jwk) {
      return { valid: false, reason: 'Missing jwk in header' };
    }

    // 3. Verify public key matches registered key
    const publicKeyThumbprint = await calculateJwkThumbprint(header.jwk);
    const registeredThumbprint = await calculateJwkThumbprint(registeredPublicKeyJwk);

    if (publicKeyThumbprint !== registeredThumbprint) {
      return {
        valid: false,
        reason: 'Public key mismatch (not registered for this partner)'
      };
    }

    // 4. Verify JWT signature using public key from header
    const publicKey = await importJWK(header.jwk, 'ES256');
    const { payload } = await jwtVerify(dpopProofJwt, publicKey);

    // 5. Verify claims
    const now = Math.floor(Date.now() / 1000);

    // Check iat (issued at) - must be recent
    if (!payload.iat || now - (payload.iat as number) > 60) {
      return { valid: false, reason: 'DPoP proof too old (must be <60s)' };
    }

    // Check htm (HTTP method)
    if (payload.htm !== request.method) {
      return {
        valid: false,
        reason: `HTTP method mismatch (expected ${request.method}, got ${payload.htm})`
      };
    }

    // Check htu (HTTP URL)
    if (payload.htu !== request.url) {
      return {
        valid: false,
        reason: `URL mismatch (expected ${request.url}, got ${payload.htu})`
      };
    }

    // Check ath (access token hash)
    const expectedHash = createHash('sha256')
      .update(request.accessToken)
      .digest('base64url');

    if (payload.ath !== expectedHash) {
      return {
        valid: false,
        reason: 'Access token hash mismatch (token not bound to proof)'
      };
    }

    // 6. Check for replay (jti uniqueness)
    const jti = payload.jti as string;
    if (await isJtiUsed(jti)) {
      return { valid: false, reason: 'Replay detected (jti already used)' };
    }

    // Mark jti as used
    await markJtiUsed(jti, 60); // Store for 60 seconds

    return {
      valid: true,
      claims: payload,
      publicKeyThumbprint
    };
  } catch (error) {
    return {
      valid: false,
      reason: `Validation error: ${error.message}`
    };
  }
}

/**
 * Calculate JWK thumbprint (RFC 7638).
 */
async function calculateJwkThumbprint(jwk: any): Promise<string> {
  // Sort JWK members lexicographically and hash
  const sorted = JSON.stringify({
    crv: jwk.crv,
    kty: jwk.kty,
    x: jwk.x,
    y: jwk.y
  });

  return createHash('sha256').update(sorted).digest('base64url');
}

/**
 * Check if JTI has been used (replay protection).
 */
async function isJtiUsed(jti: string): Promise<boolean> {
  // Check Redis/database
  const exists = await redis.exists(`dpop:jti:${jti}`);
  return exists === 1;
}

/**
 * Mark JTI as used.
 */
async function markJtiUsed(jti: string, ttlSeconds: number): Promise<void> {
  // Store in Redis with TTL
  await redis.setex(`dpop:jti:${jti}`, ttlSeconds, '1');
}
```

#### Phase 3: Partner API Middleware

**File:** `lib/middleware/dpopAuth.ts`
```typescript
import { NextRequest, NextResponse } from 'next/server';
import { validateDPoPProof } from '@/lib/security/dpopValidator';

/**
 * Middleware to enforce DPoP authentication for partner APIs.
 */
export async function dpopAuthMiddleware(request: NextRequest) {
  // Extract headers
  const authHeader = request.headers.get('authorization');
  const dpopHeader = request.headers.get('dpop');

  // Check for DPoP scheme
  if (!authHeader?.startsWith('DPoP ')) {
    return NextResponse.json(
      { error: 'Missing DPoP authorization' },
      { status: 401, headers: { 'WWW-Authenticate': 'DPoP' } }
    );
  }

  if (!dpopHeader) {
    return NextResponse.json(
      { error: 'Missing DPoP proof header' },
      { status: 401 }
    );
  }

  // Extract access token
  const accessToken = authHeader.substring(5); // Remove "DPoP "

  // Verify access token exists and is DPoP-bound
  const tokenRecord = await db.partnerTokens.findUnique({
    where: { token: accessToken },
    include: { partner: { include: { dpopPublicKey: true } } }
  });

  if (!tokenRecord) {
    return NextResponse.json(
      { error: 'Invalid access token' },
      { status: 401 }
    );
  }

  if (!tokenRecord.dpopBound) {
    return NextResponse.json(
      { error: 'Token not DPoP-bound (use bearer auth or upgrade to DPoP)' },
      { status: 401 }
    );
  }

  // Validate DPoP proof
  const validation = await validateDPoPProof(
    dpopHeader,
    {
      method: request.method,
      url: request.url,
      accessToken
    },
    tokenRecord.partner.dpopPublicKey.jwk
  );

  if (!validation.valid) {
    return NextResponse.json(
      { error: `DPoP validation failed: ${validation.reason}` },
      { status: 401 }
    );
  }

  // Attach partner context to request
  (request as any).partner = tokenRecord.partner;
  (request as any).dpopValidation = validation;

  return NextResponse.next();
}
```

## Issue #855: Centralized Authorization with Cedar Policy Engine

### Problem Statement

**Current State:**
- Authorization logic scattered across:
  - RLS policies (Postgres)
  - Route handlers (`app/api/**`)
  - Server actions
  - Helper functions (`lib/auth/admin-session.ts`)
- Complex roles: patients, guardians, CHWs, clinicians, partners, operators
- No single source of truth
- Policy changes require reading dozens of files
- Cannot test "who can do what" holistically

**Example of Scattered Logic:**
```typescript
// lib/auth/admin-session.ts
if (user.role !== 'admin') throw new Error('Forbidden');

// app/api/patients/[id]/route.ts
if (session.role !== 'clinician' && session.userId !== patientId) {
  return { error: 'Forbidden' };
}

// RLS policy
CREATE POLICY patients_read ON patients FOR SELECT USING (
  auth.uid() = user_id OR 
  auth.uid() IN (SELECT user_id FROM guardians WHERE patient_id = patients.id)
);

// Problem: Same authorization logic expressed 3 different ways!
```

**Impact:**
- High: Inconsistent authorization decisions
- Maintainability: Policy changes require touching many files
- Auditability: Cannot prove "who can access what"
- Testing: No way to exhaustively test all permission combinations

### Technical Analysis

**Cedar Policy Language (AWS Open Source):**
```
// Declarative, type-safe, testable
permit(
  principal == User::"alice",
  action == Action::"read",
  resource == Patient::"patient-123"
);

// Or with conditions
permit(
  principal in Role::"clinician",
  action == Action::"break_glass_access",
  resource in ResourceType::"Patient"
)
when {
  context.emergency == true &&
  context.has_justification == true
};
```

**Cedar Benefits:**
1. **Single Source of Truth:** All policies in one place
2. **Declarative:** What to allow, not how to enforce
3. **Type-Safe:** Schemas prevent policy errors
4. **Testable:** Exhaustive test suites for all scenarios
5. **Versioned:** Policies in Git, reviewable like code
6. **Auditable:** Query "who can access resource X?"

```typescript
// Initialize Cedar engine
export const cedarEngine = new AuthorizationEngine();

// Load policies from files
import policies from './policies/policies.cedar?raw';
import schema from './policies/schema.cedar?raw';

cedarEngine.setSchema(schema);
cedarEngine.addPolicies(policies);

export interface AuthorizationRequest {
  principal: string;    // User::"user-123" or Role::"clinician"
  action: string;       // Action::"read_patient"
  resource: string;     // Patient::"patient-456"
  context?: Record<string, any>;
}

export async function isAuthorized(
  request: AuthorizationRequest
): Promise<boolean> {
  const result = cedarEngine.isAuthorized({
    principal: request.principal,
    action: request.action,
    resource: request.resource,
    context: request.context || {}
  });

  return result.decision === 'Allow';
}
```

```cedar
// Policy 1: Patients can read their own data
permit(
  principal,
  action == Action::"read_patient",
  resource
)
when {
  principal == resource.user
};

// Policy 2: Guardians can read their patients
permit(
  principal,
  action == Action::"read_patient",
  resource
)
when {
  resource in principal.isGuardianOf
};

// Policy 3: CHWs can read assigned patients
permit(
  principal in Role::"chw",
  action == Action::"read_patient",
  resource
)
when {
  principal in resource.assignedCHWs
};

// Policy 4: Clinicians can break-glass access with justification
permit(
  principal in Role::"clinician",
  action == Action::"break_glass_access",
  resource in ResourceType::"Patient"
)
when {
  context.emergency == true &&
  context.has_justification == true &&
  context.has_approval == true
};

// Policy 5: Operators can audit with approved elevation
permit(
  principal in Role::"operator",
  action == Action::"admin_audit",
  resource
)
when {
  context.has_active_elevation == true &&
  context.elevation_scope contains "audit"
};

// Policy 6: Deny all by default (explicit deny)
forbid(
  principal,
  action,
  resource
)
unless {
  // Explicitly allowed by above policies
  false
};
```

## Issue #856: Just-in-Time Privileged Access

### Problem Statement

**Current State:**
- Admin access is **standing privilege** (never expires)
- Once granted, access remains until manually revoked
- No justification required
- No time limits
- Standing access = primary breach amplifier

**Problem:**
```
Operator granted admin role → Access forever
  - Even when not actively needed
  - Even after project ends
  - Even if operator changes role
  - Maximum blast radius for compromised account
```

**Impact:**
- Critical: Violates least-privilege principle
- Compliance: Audit finding under SOC 2, HIPAA
- Risk: Unnecessary exposure window

### Technical Analysis

**Just-in-Time (JIT) Access:**
```
1. Operator requests elevation:
   - Scope: "audit_explorer", "admin_console", "ops_cli"
   - Justification: "Investigating incident INC-123"
   - Duration: 1 hour (or until task complete)
   
2. Approval required (for PHI-touching scopes)
   - Second operator reviews and approves
   
3. Grant issued with expiration
   - Time-boxed access
   - Automatically revoked after duration
   
4. Full audit trail
   - Who, what, when, why
   - Approval chain
   - What was accessed during elevation
```

#### Phase 2: JIT Access Service

```typescript
export async function requestElevation(
  principalId: string,
  scope: 'audit_explorer' | 'admin_console' | 'ops_cli',
  reason: string,
  ticketRef: string,
  durationMinutes: number = 60
) {
  const requiresApproval = phiTouchingScopes.includes(scope);
  const expiresAt = new Date(Date.now() + durationMinutes * 60 * 1000);

  const grant = await db.privilegeGrants.create({
    data: {
      principalId,
      scope,
      reason,
      ticketReference: ticketRef,
      requiresApproval,
      expiresAt
    }
  });

  if (requiresApproval) {
    await notifyApprovers(grant);
  }

  return grant;
}

export async function hasActiveElevation(
  principalId: string,
  scope: string
): Promise<boolean> {
  const now = new Date();
  const grant = await db.privilegeGrants.findFirst({
    where: {
      principalId,
      scope,
      expiresAt: { gt: now },
      revokedAt: null,
      OR: [
        { requiresApproval: false },
        { approvedAt: { not: null } }
      ]
    }
  });

  return grant !== null;
}
```
